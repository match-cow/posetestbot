The problem it solves

A pose dataset is more than a folder of images.

Useful 6D pose research depends on knowing which camera model, robot pose, object geometry, timestamp policy, and validation result belongs to every frame. PoseTestBot captures that chain of evidence alongside the pixels, instead of reconstructing it later from lab notes.

A safe first look

Open the console without touching hardware.

Installation and navigation do not start a capture. Binding the console to loopback keeps this first run on your machine.

Terminal 
# Python 3.12; uv is installed if needed
git clone https://github.com/match-cow/PoseTestBot.git
cd PoseTestBot
bash scripts/install.sh

# Keep the first launch on this computer
POSETESTBOT_WEB_HOST=127.0.0.1 uv run posetestbot-web

Then open 127.0.0.1:5000. Missing lab devices are reported as status; they are not opened automatically.

Physical execution boundary

A green check is not permission to move.

Real capture is only for the supervised lab cell. It requires an operator, explicit authorization, and both fresh execution safety gates. Readiness checks do not open cameras, reserve hardware, or authorize robot motion.

  • Supported robot: the lab KUKA LBR iiwa profile only.
  • Never use iiwa UDP STOP between calibration captures: it cannot interrupt active motion and exits the waiting program.
  • Console exposure: it is unauthenticated; keep it on localhost or the trusted lab network.

Evidence, not just output

Each layer answers a different question.

Processing adds derived artifacts. It does not rename or delete the only copy of captured frames and robot poses.

01 / RAW

What did the cell observe?

RGB-D frames, per-frame timestamp metadata, camera sidecars, and the original robot pose stream.

  • rgb/ + depth/
  • frame_metadata.jsonl
  • raw_robot_ee_poses.json
02 / DERIVED

Why are the frames usable?

Non-destructive frame-to-pose matches, synchronization quality, selected calibrations, validation, and job reports.

  • processed/synchronized/
  • sync_quality_report.json
  • calibration_profile_selection.json
03 / PORTABLE

What can another tool consume?

A standard BOP dataset with scenes, cameras, models, targets, frame mapping, and compact PoseTestBot provenance.

  • bop/test/ + bop/models/
  • test_targets_bop19.json
  • bop_export_manifest.json
Optional

Ground truth and evaluation evidence

Pose ground truth can be added when placement is known. The full mode adds masks, visible masks, ROI, and visibility data. The separate Inspect-only BOP19 path validates an already annotation-bearing export; it is not an acquisition stage or an estimator.

Plain-language glossary

A few terms used throughout the project.

What is a 6D object pose?

An object's 3D position—x, y, and z—plus its 3D orientation. Together, those six values describe where the object is and how it is rotated.

What is BOP?

BOP is a standard dataset and benchmark format for 6D object-pose research. Exporting BOP lets downstream tools consume scenes, cameras, models, targets, and optional annotations without a PoseTestBot-specific converter.

What does “run-owned” mean?

A physical acquisition has one folder. Its configuration and selected reusable inputs are snapshotted into that run, so later library edits cannot silently change its meaning.

What is a pose template?

An immutable, printable layout that identifies objects and their planned placement. A dataset run records the measured transform from that layout to the cell's template-base frame.

Can PoseTestBot run a pose estimator?

No. Its pipeline ends at a validated BOP dataset. A separate companion can orchestrate qualified estimators and return a standard BOP19 result CSV through a narrow handoff.
